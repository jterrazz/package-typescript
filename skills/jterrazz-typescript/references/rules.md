# The rulebook, rule by rule

Every rule of every plugin the toolchain loads, with what the rulebook says about it — the table below is GENERATED from `rules/` and is never hand-edited.

Three things a reader needs before the table. `on` always means `error`: there is no warn tier anywhere in this toolchain. An `off` always carries one of five reasons — `formatter`, `exclusive`, `convention`, `evidence`, `covered` — and "too strict" is not among them. A profile adds a framework's plugins and its ignore patterns; it never relaxes what every profile shares, so a rule marked `all` is on in every project of the estate.

Why each decision was taken, the version it was taken in, and the five reason kinds in full are the package's own chapter: `docs/07-lint-presets.md`.

Every `vitest/*` row reads "scoped to test files" and names no glob. Which file shapes are test files, and where each kind of spec lives, is `@jterrazz/test`'s to decide and its catalogue's to state — this page would otherwise carry a second copy that drifts, and one of the globs it used to print names a layout that package's own rulebook refuses.
